trust2-contract Reference

English

简介

这是 trust2-contract 的用户手册。trust2-contract 是一个基于契约的 Rust 验证工具。

安装

在 Linux AMD64、macOS AMD64 或 macOS ARM64 上从源码构建 trust2-contract。下面创建本地 OCaml 环境，并先使用 Alt-Ergo 作为证明器。命令适用于 Bash 或 Zsh。

1. 准备系统工具

安装 Git、C/C++ 构建工具链和 opam。

Debian 或 Ubuntu：

sudo apt update
sudo apt install git curl build-essential pkg-config libgmp-dev opam

macOS：如果尚未安装 Command Line Tools，先安装它，再通过 Homebrew 安装 opam：

xcode-select --install
brew install git opam pkg-config

其他发行版参考 opam 安装说明。解析依赖时，opam 可能提示安装额外的系统软件包。

2. 获取源码

git clone https://github.com/OpenSourceVerif/trust2-contract.git
cd trust2-contract

这里是仓库根目录，包含 Cargo.toml、rust-toolchain.toml 和 trust2-contract.opam。除非另行说明，后续配置命令均在这里执行。请保留这份源码，当前契约库通过路径依赖接入项目。

3. 配置 Rust

如果尚未安装 rustup，使用 Rust 官方安装器：

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
. "$HOME/.cargo/env"

在仓库根目录检查选中的工具链：

rustc --version
rustup show active-toolchain

Rustup 会读取仓库的 rust-toolchain.toml，在需要时下载指定工具链和组件。当前文件固定为 nightly-2026-06-01，并包含 rustc-dev、llvm-tools 和 miri。前端依赖 Rust 编译器内部接口，因此应使用当前源码对应的工具链文件。

4. 配置 OCaml 环境

首次使用 opam 时，先初始化，并暂不创建全局 switch：

opam init --bare

按仓库的开发配置创建本地 OCaml switch，激活环境，再安装项目依赖：

opam switch create . 5.3.0
eval $(opam env)
opam install . --deps-only

如果这份源码已经有本地 switch，直接复用即可。依赖清单固定了 Why3find 的一个开发版本；通过 opam install . --deps-only 安装，以遵循该版本配置。

检查当前环境能否找到 Why3find：

command -v why3find

打开新终端后，先回到仓库根目录执行 eval $(opam env)，再运行验证器。这会将本地 switch 的可执行文件加入 PATH，随后进入示例目录也能继续使用。switch 管理方式见 opam 使用说明。

5. 安装证明器

执行验证除了需要 Why3find，还需要外部证明器。可以先在同一个 switch 中安装 Alt-Ergo，再让 Why3 检测它：

opam install alt-ergo
why3 config detect
why3 config list-provers

确认检测结果中包含 Alt-Ergo。之后安装其他证明器时，应重新运行检测，详见 Why3 配置说明。

验证器的默认证明器列表为 Alt-Ergo、CVC5 和 Z3。下面的示例显式选择 Alt-Ergo，只请求这份安装流程中配置的证明器。安装并检测其他证明器后，可通过 --prover 选择，例如 --prover alt-ergo,z3。

6. 安装验证器

在仓库根目录执行：

cargo install --path ./cargo-verify
cargo verify --help

Cargo 通常将 cargo-verify 安装到 ~/.cargo/bin。该目录和当前 opam switch 的 bin 目录都需要保留在 PATH 中。

7. 检查安装结果

运行仓库自带的示例：

cd examples/readme
cargo verify --prover alt-ergo

这一步一起检查 Rust 前端、规约转换和证明器调用。成功时应以 Verified 摘要结束，并正常退出；只运行 --help 仅能确认命令已安装。

接下来阅读基本用法，将契约库接入自己的包。

常见问题

  • 找不到 cargo verify： 检查 Cargo 安装目录是否在 PATH 中；默认 rustup 配置下，可重新加载 . "$HOME/.cargo/env"。
  • 找不到 why3find： 在运行验证的终端中，回到仓库根目录执行 eval $(opam env)，激活本地 switch。
  • 没有匹配的证明器： 检查 why3 config list-provers，确认可执行文件位于 PATH 中，并重新执行 why3 config detect。
  • Rust 编译器或组件不匹配： 使用源码自带的 rust-toolchain.toml，不要替换为其他 nightly。

基本用法

完成安装后，将仓库的 rust-toolchain.toml 复制到项目包的根目录，并在 Cargo.toml 中添加 trust2-contract：

[dependencies]
trust2-contract = { path = "/path/to/trust2-contract/trust2-contract" }

将路径替换为本地源码中 trust2-contract 库所在的目录。

编写契约

导入契约标注，并将它们添加到函数上：

use trust2_contract::prelude::*;

#[precondition(x < 16)]
#[postcondition(|result| result >= x)]
pub fn square(x: u8) -> u8 {
    x * x
}

前置条件要求调用者传入的 x 小于 16。后置条件将返回值命名为 result，并声明它不小于 x。

这个函数既可以放在库中，也可以放在可执行程序中。

在库中使用

将上面的代码放入 src/lib.rs，在包的根目录执行：

cargo verify --prover alt-ergo -- --lib

验证器在前置条件成立的假设下检查函数，不需要额外编写 main 函数。

在可执行程序中使用

将同样的代码放入 src/main.rs，并添加程序入口：

fn main() {
    let _ = square(4);
}

然后执行：

cargo verify --prover alt-ergo -- --bin my-app

将 my-app 替换为可执行目标的名称，默认就是 Cargo.toml 中的包名。这里 main 传入的 4 满足 square 的前置条件。

两条命令都使用安装时配置的 Alt-Ergo 证明器。-- 后的参数用于选择 Cargo 目标：--lib 选择库，--bin 选择可执行程序。命令在包目录中执行；工作区成员也在各自的包目录中执行。

正常运行可执行程序使用 cargo run。普通构建会移除契约标注，静态检查契约则使用 cargo verify。

前置条件与后置条件的更多用法见函数契约。

[contract.specifications]

规约语言

规约描述函数调用、程序状态和数据应满足的条件，以 Rust 属性和宏调用的形式书写。

[contract.specifications.syntax]

Syntax
Specification :=
      FunctionContract
    | TypeInvariant
    | ContractStatement

词法规则定义本参考手册使用的记号和 Rust 语法约定；逻辑表达式定义构成规约条件的表达式。

后续章节说明这些条件的作用位置：

  • 函数契约：调用时的要求和返回时的保证。
  • 语句标注：函数体内某个位置的断言和假设。
  • 类型不变式：与类型关联的条件。

每种构造分别说明语法、语义、示例和实现边界。文法索引汇总全部产生式。

[contract.lexical]

词法规则

规约写在 Rust 源码中。函数契约和类型不变式使用属性；语句标注和量词使用宏调用。注释不用于引入规约。

词法单元与标识符

标识符、字面量、空白和注释遵循 Rust 的词法规则。空白和普通注释可以出现在 Rust 允许的词法单元之间。规约语言没有引入独立的字面量记法或数学 Unicode 运算符。

文法中的以下名称引用 Rust 语法：

名称含义示例
IDENTIFIER标识符x、result、limit
Type类型u8、&T、Vec<i32>
Literal字面量表达式true、16、0u8
Path表达式路径x、u8::MAX
TUPLE_INDEX元组字段索引pair.0 中的 0

绑定引入的名称遵循 Rust 的作用域规则。后置条件中的 result 是普通参数名，可以换成其他标识符。类型不变式中的 self 指代被描述的值。

文法记号

Syntax 块使用紧凑的扩展 BNF（EBNF）。带边框的等宽文本表示源码中的字面词法单元；带链接的名称表示非终结符。

记号含义
A := B用 B 定义 A
A BA 后接 B
A | BA 或 B
A?A 出现零次或一次
A*A 出现零次或多次
(A B)对文法元素分组

带边框的 (、) 或 | 是源码词法单元，不是文法运算符。Arguments? 允许省略参数列表；","? 允许尾随逗号。Show syntax diagrams 按钮显示同一产生式的铁路图。

文法采用不带路径限定的名称、圆括号宏调用和简单参数绑定。Expr 产生式描述表达式结构，分组由 Rust 的运算符优先级决定；它不是覆盖全部 Rust 表达式的无歧义解析文法。

示例

#[precondition(x /* input */ < 16)]
#[postcondition(|result: u8| result >= x)]

注释分隔词法单元，不改变前置条件。第二个属性中的竖线界定返回值绑定。

实现边界

  • 前端 rust-llbc：沿用 Rust 词法、表达式解析以及类型与借用检查。
  • 后端 llbc-why3：处理提取后的表示，不直接处理这些词法形式。

尚待补齐

区分标记与普通名称（前端）。 当前按名称替换 implies 和后置条件中的 old，会误改普通 Rust 名称。例如 #[postcondition(|r| r == value.old())] 中的 .old() 即使是用户定义的方法，也会受到替换，导致展开失败。名称处理需要保留普通方法调用，同时识别规约标记，见名称改写。

[contract.expression]

逻辑表达式

逻辑表达式构成契约、语句标注和类型不变式中的条件。它们使用 Rust 表达式，并扩展了量词、蕴含和旧状态标记。

[contract.expression.syntax]

Syntax
Condition :=
      Expr

Expr :=
      Literal
    | Path
    | self
    | ( Expr )
    | UnaryOp Expr
    | Expr BinaryOp Expr
    | Expr . Field
    | Expr [ Expr ]
    | Expr ( Arguments? )
    | Expr . IDENTIFIER ( Arguments? )
    | Quantifier
    | Implication
    | OldExpression

Arguments :=
      Expr (, Expr)* ,?

Field :=
      IDENTIFIER
    | TUPLE_INDEX

UnaryOp :=
      ! | - | * | & | & mut

BinaryOp :=
      + | - | * | / | % | << | >> | & | ^ | | | == | != | < | <= | > | >= | && | ||

[contract.expression.intro]

类型与值

Condition 必须具有 bool 类型。子表达式可以具有其他 Rust 类型：例如，在 x + 1 <= limit 中，加法产生数值，比较产生布尔值。当前没有独立的谓词类型，也不将整数隐式转换为布尔条件。

名称引用作用域内的绑定。字段访问、解引用、索引、函数调用和方法调用遵循 Rust 的类型与借用规则。圆括号用于分组，不改变表达式的值。

整数表达式使用 Rust 整数类型，遵循其有限取值范围和算术检查。规约接口没有引入数学整数或实数。访问集合元素的表达式同样必须满足索引边界要求；表达式出现在规约中不会免除这一要求。

运算符

下表按优先级从高到低排列。一元运算符右结合，算术和位运算的二元运算符左结合。比较不能直接连写，应写成 a < b && b < c。

分组运算符
访问与调用e.field e[i] f(x) e.method(x)
一元运算! - * & &mut
乘除与取余* / %
加减+ -
移位<< >>
按位与&
按位异或^
按位或|
比较== != < <= > >=
逻辑与&&
逻辑或||
蕴含==>（右结合）

对布尔操作数，!、&& 和 || 分别表示否定、合取和析取。&& 和 || 短路求值，只有需要时才求值右操作数。单字符的位运算符不提供这种短路行为。

量词绑定某个 Rust 类型的值；蕴含表达条件命题；旧状态表达式说明后置条件中可用的前状态标记。

[contract.expression.example]

示例

use trust2_contract::prelude::*;

#[precondition(i < values.len() && values[i] > 0)]
pub fn positive_at(values: &[u8], i: usize) -> u8 {
    values[i]
}

该条件要求索引有效且对应元素为正。短路求值保证仅在索引合法时才求值第二个操作数。

前端已有切片长度、Vec 索引、字段比较和普通调用等表达式的提取用例；后端对这些表达式的支持仍有差异，见下文。

条件也可以使用 Rust 表达式块、局部绑定、类型转换和分支。例如，下面的前置条件能够提取：

#[precondition({
    let y = x as u32;
    if flag { y > 0 } else { y == 0 }
})]
pub fn selected(x: u8, flag: bool) -> u8 {
    x
}

枚举条件可以使用 match，见类型不变式中的示例。普通函数调用也能进入规约，例如 #[precondition(positive(x))]，其中 positive 是返回 bool 的 Rust 函数。这些表达式能提取，不表示其所有操作都已接入后端验证。

[contract.expression.boundary]

实现边界

  • 前端 rust-llbc：已能提取基本运算、字段访问、切片访问、普通调用，以及条件中的 if、match 和类型转换。
  • 后端 llbc-why3：已支持基础标量表达式；切片、索引、usize、部分枚举与 trait 操作仍有缺口。

尚待补齐

切片条件（后端）。 上例的 i < values.len() && values[i] > 0 可以提取，但验证还需要切片、长度、下标类型和索引操作的翻译，以便表达“索引有效且元素为正”。

规约中的函数调用（前后端，规则待明确）。 #[precondition(positive(x))] 这类普通调用可以进入 LLBC。当前前端也会接受调用一个修改全局状态、再返回 bool 的函数；Fn + Copy 约束本身并不排除这种副作用。哪些函数可以用于规约、如何约束其副作用，需要先明确，再由前端检查和后端逻辑表示共同落实。普通调用能够提取，还不足以保证它可作为逻辑条件完成验证。

[contract.quantifier]

量词

[contract.quantifier.syntax]

Syntax
Quantifier :=
      (forall | exists) ! ( QuantifierPredicate )
    | each ! ( IDENTIFIER : Type EachDomain ; Condition )

QuantifierPredicate :=
      | IDENTIFIER : Type | Condition

EachDomain :=
      ; Condition
    | in Expr .. Expr
    | in Expr ..= Expr

[contract.quantifier.intro]

语义

forall!(|x: T| P) 表示对类型 T 的每个值 x，P 都成立。exists!(|x: T| P) 表示存在类型 T 的某个值 x，使 P 成立。两种形式中的 P 都必须具有 bool 类型。

x 的绑定作用域是闭包体。闭包体可以引用外部绑定，也可以包含其他量词。多个量化变量可以通过嵌套量词表达，也可以将一个元组作为参数并解构。每个量词接受一个参数，|x: u8, y: u8| 这样的双参数闭包不符合当前接口。

量化域是 Rust 类型。例如，对 u8 的量化涉及其有限取值范围，而非无界数学整数。对量化域的限制写在量词体中：全称量化使用条件性质，存在量化则要求范围限制和性质同时成立。

each! 是带显式定义域的全称量词：

  • each!(i: T; G; P) 表示：对类型 T 中每个满足 G 的 i，P 都成立。
  • each!(i: T in a..b; P) 相当于 G 取 a <= i && i < b。a..=b 包含 b。

只有定义域内的值才会求值 P，因此 each!(i: usize in 0..v.len(); v[i] > 0) 不会读取切片范围之外的元素。区间必须写出上下界，上下界不必是常量。

[contract.quantifier.example]

示例

use trust2_contract::prelude::*;

#[postcondition(|result| forall!(|i: u8| i <= result))]
pub fn largest_u8() -> u8 {
    u8::MAX
}

#[postcondition(|result| exists!(|i: u8| i == result))]
pub fn zero() -> u8 {
    0
}

第一个后置条件给出所有 u8 值的上界。第二个后置条件声明，在同一类型中存在一个值与返回值相等。

这两个例子中的量词及返回值绑定都能进入 LLBC，并生成对应的 WhyML 量化条件。

元组参数可以同时引入两个变量。例如，下面的条件表示任取两个 u8 值，它们相等或返回值为零：

#[postcondition(|r| forall!(|(x, y): (u8, u8)| x == y || r == 0))]
pub fn zero_for_pairs() -> u8 {
    0
}

这一写法也能提取并生成 WhyML。

each! 直接限定定义域。下面两种写法都表示：界以下的每个 i 都小于返回值：

#[postcondition(|r| each!(i: u8; i < n; i < r))]
pub fn with_guard(n: u8) -> u8 {
    n
}

#[postcondition(|r| each!(i: u8 in 0..n; i < r))]
pub fn with_range(n: u8) -> u8 {
    n
}
[contract.quantifier.boundary]

实现边界

  • 前端 rust-llbc：已有三种量词及嵌套量词的提取，元组参数和捕获的外层变量都能保留。each! 由宏展开为 forall!，在 LLBC 中表现为带定义域分支的全称量词。
  • 后端 llbc-why3：已有全称与存在量词翻译，但生成文件不代表绑定和条件均已正确处理。

尚待补齐

区间与切片上的量化（后端）。 涉及切片的条件受相应表达式的支持限制。例如“所有有效下标对应的元素都为正”，需要量词、长度和索引操作一起工作。

[contract.implies]

蕴含

[contract.implies.syntax]

Syntax
Implication :=
      Condition ==> Condition
    | implies ( Condition , Condition ,? )

[contract.implies.intro]

语义

P ==> Q 表示逻辑蕴含：仅在 P 为真且 Q 为假时为假。P 和 Q 都具有 bool 类型。

==> 的优先级低于其他所有运算符，并且右结合：a && b ==> c == d 表示 (a && b) ==> (c == d)，a ==> b ==> c 表示 a ==> (b ==> c)。要把结果作为操作数使用，需要加括号，例如 (a ==> b) && c。写在 if 或 match 之后的条件同样要加括号：if (a ==> b) { ... }。

规约宏把 P ==> Q 改写为 !(P) || (Q)，因此只有 P 成立时才求值 Q。这样，关于下标的条件可以保护依赖它的访问，例如 i < v.len() ==> v[i] > 0。

implies(P, Q) 的真值表相同，但它是普通调用，两个参数都会求值。建议使用 ==>。

[contract.implies.example]

示例

use trust2_contract::prelude::*;

#[postcondition(|result| x > 0 ==> result >= x)]
pub fn identity(x: i32) -> i32 {
    x
}

#[precondition(forall!(|i: usize| i < v.len() ==> v[i] > 0))]
pub fn all_positive(v: &[u8]) {}

第一个后置条件要求：只要 x > 0，就有 result >= x。第二个条件不会读取切片范围之外的 v[i]。

[contract.implies.boundary]

实现边界

  • 前端 rust-llbc：==> 由规约宏改写，在 LLBC 中表现为分支，没有专门的标记。implies 被识别并作为标记保留在 LLBC 中。
  • 后端 llbc-why3：==> 翻译为 WhyML 条件表达式，例如 if x > 0 then result >= x else true。implies 标记尚未翻译。涉及切片的条件受后端切片支持限制。

尚待补齐

implies 标记（后端）。 implies(x > 0, result >= x) 需要翻译；也可以移除 implies，统一使用 ==>。

[contract.old]

旧状态表达式

[contract.old.syntax]

Syntax
OldExpression :=
      old ( Expr ,? )

[contract.old.intro]

语义

后置条件中的旧状态表达式引用函数的前状态，即进入函数时的状态，用于描述返回时状态与先前状态之间的关系。

old(p) 接受函数的一个可变引用参数 p，表示该引用在入口处的状态：*old(p) 是入口时 p 指向的值，*p 是返回时的值。old 是作用于参数的标记，而不是对任意 Rust 表达式的快照操作：不接受 old(*p)、old(x + 1) 或 old(v.len())。只有 &mut 参数的入口值会与返回值不同；其他参数本来就表示入口值。

[contract.old.example]

示例

use trust2_contract::prelude::*;

#[precondition(*p < u32::MAX)]
#[postcondition(|_| *p == *old(p) + 1)]
pub fn increment(p: &mut u32) {
    *p += 1;
}

#[postcondition(|_| forall!(|i: usize| implies(i < v.len(), v[i] == old(v)[i] / 2)))]
pub fn halve_all(v: &mut [u32]) {
    for x in v.iter_mut() {
        *x /= 2;
    }
}

old 可以出现在后置条件内嵌套的量词中，也适用于切片等动态大小的被指向类型。后置条件宏把 old(p) 改写为 old(&p)，使闭包以共享引用捕获 p，从而保持 Fn + Copy；参数不是 &mut 时产生类型错误。

[contract.old.boundary]

实现边界

  • 前端 rust-llbc：把 old(p) 提取为 SpecOld 调用，其参数是后置条件对 p 的捕获。在后置条件以外使用 old，或参数不是函数的参数（例如返回的引用、量词变量或字段 old(s.f)）时报错。
  • 后端 llbc-why3：尚未实现旧状态翻译；SpecOld 和可变借用还不能翻译。

尚待补齐

可变参数的入口值（后端）。 对上面的 increment，后端需要利用可变引用的二元组表示，把 *old(p) 翻译为 *p 的入口值，把 *p 翻译为返回时的值。

字段与复合值（前后端）。 对 s: &mut S 及其字段 f: &mut T，*s.f 的入口值如何表示，以及经由多个引用可达的数据如何保留旧状态，范围仍待明确。

[contract.function]

函数契约

函数契约规定调用函数时需要满足的条件，以及函数正常返回时保证的条件。

[contract.function.syntax]

Syntax
FunctionContract :=
      Precondition
    | Postcondition

[contract.function.intro]

语义

前置条件描述调用者的义务，也是验证函数体时采用的假设。后置条件描述函数返回时的义务。

属性放在函数定义之前。前置条件和后置条件可以重复声明，也可以交错排列。所有已声明的前置条件都必须满足，所有已声明的后置条件都需要建立。后置条件本身不声明函数终止。

后置条件通过闭包参数绑定返回值，参见返回值绑定。对先前状态的引用使用旧状态表达式，其当前接口仍有限制。

[contract.function.example]

示例

use trust2_contract::prelude::*;

#[precondition(x < 16)]
#[postcondition(|result| result >= x)]
pub fn square(x: u8) -> u8 {
    x * x
}

前置条件将 x 限制在平方结果能够用 u8 表示的范围内。后置条件要求返回值不小于 x。

这个例子已支持前端提取和后端验证。前置条件和后置条件也可以分别使用，或在同一函数上声明多个。

方法上的条件可以引用 self。下面的契约能够提取并生成 WhyML：

pub struct Counter {
    value: u32,
}

impl Counter {
    #[precondition(self.value < 10)]
    #[postcondition(|r| r == self.value)]
    pub fn get(&self) -> u32 {
        self.value
    }
}
[contract.function.boundary]

实现边界

  • 前端 rust-llbc：已支持普通函数和带函数体的方法上的前置／后置条件。
  • 后端 llbc-why3：已支持基本标量函数的契约验证；泛型函数和 trait 声明仍有翻译限制。

尚待补齐

无函数体的声明（前端）。 当前宏通过函数体携带条件，下面的写法无法展开：

trait Reader {
    #[postcondition(|result| result <= 100)]
    fn read(&self) -> u8;
}

这里需要能把条件保存到方法声明上，供后续处理实现和调用时使用。契约如何由实现沿用，以及是否允许加强保证，仍待明确。

特殊函数形式（前端）。 #[precondition(x < 100)] const fn f(x: u32) -> u32 { x } 的展开会调用非常量辅助函数；#[postcondition(|r| r > 0)] async fn f() -> u32 { 1 } 则在前端提取时遇到尚不支持的协程类型。要覆盖这些形式，需要分别适配常量上下文，以及异步函数完成后得到的返回值。

[contract.precondition]

前置条件

[contract.precondition.syntax]

Syntax
Precondition :=
      # [ precondition ( Condition ) ]

语义

#[precondition(P)] 要求布尔条件 P 在进入函数时成立。在调用处，调用者必须建立 P；验证函数体时，将 P 作为假设。

条件可以引用函数参数、方法接收者，以及定义处可见的其他名称。前置条件不绑定返回值。多个前置条件属性要求其中的条件全部成立。

示例

use trust2_contract::prelude::*;

#[precondition(divisor != 0)]
pub fn quotient(value: u32, divisor: u32) -> u32 {
    value / divisor
}

前置条件排除了除零情况。以 divisor == 0 调用该函数不满足所声明的要求。

基本参数条件已支持前端提取。后端已有的用例包括用 x < 16 约束平方计算，以及用 a >= b 约束无符号减法。

实现边界

  • 前端 rust-llbc：已支持基本参数条件、方法接收者和多条前置条件。
  • 后端 llbc-why3：已支持基本标量条件的翻译和验证。

无函数体声明的限制见函数契约；切片访问等条件的限制见逻辑表达式。

[contract.postcondition]

后置条件

[contract.postcondition.syntax]

Syntax
Postcondition :=
      # [ postcondition ( ResultPredicate ) ]

ResultPredicate :=
      | IDENTIFIER (: Type)? | Condition

语义

#[postcondition(|result| Q)] 要求布尔条件 Q 在正常返回时成立，其中 result 绑定返回值。验证函数时，必须在前置条件成立的前提下建立这一条件。

多个后置条件声明同时成立的保证。它们不规定函数是否终止，也不规定发生 panic 时的行为。

返回值绑定

参数名可以任意选取，result 不是关键字。其类型是函数的返回类型，也可以显式写出。未声明返回类型的函数返回 ()。

函数参数和方法接收者通过外部作用域引用。捕获一个引用，本身不表示对其指向的数据创建快照。前状态记法的含义及其实现限制见旧状态表达式。

示例

use trust2_contract::prelude::*;

#[postcondition(|value: u32| value == x)]
pub fn identity(x: u32) -> u32 {
    x
}

这里 value 表示返回值，x 是参与比较的输入。

返回值条件已支持前端提取和基本后端验证。例如，最大值函数可以分别声明 result >= a 和 result >= b，同时保证结果不小于两个输入。

实现边界

  • 前端 rust-llbc：已支持闭包绑定返回值、引用输入参数和多条后置条件。
  • 后端 llbc-why3：已支持基本标量返回值条件；涉及可变引用和旧状态的关系仍不完整。

尚待补齐

直接传入函数（前端）。 以下写法能够通过 Rust 类型检查，但规约提取会失败：

fn positive(value: u32) -> bool {
    value > 0
}

#[postcondition(positive)]
pub fn one() -> u32 {
    1
}

同一个条件写成 #[postcondition(|value| positive(value))] 可以提取。直接传入函数时，还需要将它关联到返回值条件，或在入口给出明确的不支持提示；函数调用本身的验证限制见逻辑表达式。

修改前后的关系。 例如“*p 返回时比进入函数时大 1”，用 old 写作 *p == *old(p) + 1。验证它仍需要后端支持旧状态和可变引用。

[contract.statement]

语句标注

语句标注描述函数体内某个位置的条件。

[contract.statement.syntax]

Syntax
ContractStatement :=
      Assertion
    | Assumption

[contract.statement.intro]

语义

断言声明需要在当前位置建立的条件。假设提供从当前位置继续推理时采用的条件。二者都可以引用作用域内的变量，并描述标注处的状态。

[contract.statement.example]

示例

use trust2_contract::prelude::*;

pub fn check(x: u8) {
    contract_assume!(x < 16);
    contract_assert!(x <= 15);
}

断言可以由前面的假设推出。这不证明每次调用 check 时都有 x < 16。

[contract.statement.boundary]

实现边界

  • 前端 rust-llbc：已支持断言和假设，保留条件、种类及所在位置。
  • 后端 llbc-why3：分别翻译为 WhyML assert 和 assume。

具体用法与限制见断言和假设。

[contract.assertion]

断言

[contract.assertion.syntax]

Syntax
Assertion :=
      contract_assert ! ( Condition ) ;

语义

contract_assert!(P); 要求布尔条件 P 在当前位置成立。它引入一个证明义务，证明时可以使用函数前置条件、此前的假设，以及此前程序语句的效果。

示例

use trust2_contract::prelude::*;

#[precondition(x < 16)]
pub fn bounded_square(x: u8) -> u8 {
    let y = x * x;
    contract_assert!(y <= 225);
    y
}

断言描述乘法执行后局部变量 y 的值。

前端可以提取这类局部断言，也支持在条件中保留普通函数调用，例如 contract_assert!(decuple(9) == 90)。

实现边界

  • 前端 rust-llbc：已支持断言条件的提取，保留其在函数体中的位置，包括分支内的断言。
  • 后端 llbc-why3：已翻译为 WhyML assert；条件能否继续验证取决于其中的表达式和程序操作。

共同限制见逻辑表达式。普通构建移除契约断言；运行时检查使用 Rust 的 assert!。

[contract.assumption]

假设

[contract.assumption.syntax]

Syntax
Assumption :=
      contract_assume ! ( Condition ) ;

语义

contract_assume!(P); 在当前位置将布尔条件 P 引入为推理假设，不产生证明 P 的义务。

使用这一假设得到的结论以该假设成立为前提。不一致的假设会使后续证明义务空泛成立。

示例

use trust2_contract::prelude::*;

pub fn assumed_bound(x: u8, flag: bool) {
    if flag {
        contract_assume!(x <= 10);
        contract_assert!(x < 11);
    } else {
        contract_assert!(x <= 255);
    }
}

在 flag 为真的分支中，假定的上界足以推出随后的断言；另一分支的断言不使用这条假设。前端提取和 WhyML 翻译会保留这种分支关系。该标注既不检查，也不为调用者建立这个上界。

实现边界

  • 前端 rust-llbc：已支持假设提取，与断言区分，并保留所在分支。
  • 后端 llbc-why3：已翻译为 WhyML assume；条件能否继续验证取决于其中的表达式和程序操作。

共同限制见逻辑表达式。假设不产生证明自身的义务，普通构建也不会用它过滤输入。

[contract.invariant]

类型不变式

[contract.invariant.syntax]

Syntax
TypeInvariant :=
      # [ invariant ( Condition ) ]

[contract.invariant.intro]

语义

#[invariant(P)] 为结构体、枚举或联合体关联一个布尔条件 P。条件中的 self 指代被描述的值。该条件表达有效实例预期满足的性质。

声明不变式与在程序边界强制保持不变式是两项不同的能力。当前实现提供声明和提取，尚未实现自动保持检查。

[contract.invariant.example]

示例

use trust2_contract::prelude::*;

#[invariant(self.start <= self.end)]
pub struct RefRange<'a, T: PartialOrd> {
    start: &'a T,
    end: &'a T,
}

条件要求范围起点不大于终点。类型参数及其约束在不变式中仍然可用。

前端可以提取这个泛型结构体的不变式，并保留它与类型的关联。

枚举可以分别描述各变体的条件：

#[invariant(match self {
    Self::Empty => true,
    Self::Range { start, end } => start <= end,
})]
pub enum Range {
    Empty,
    Range { start: u32, end: u32 },
}

前端可以提取这个 match self 条件。联合体条件也能提取；读取字段仍需遵循 Rust 的 unsafe 要求：

#[invariant(unsafe { self.x <= 100 })]
pub union Data {
    pub x: u32,
    pub y: u32,
}

这些例子说明条件如何与类型关联，尚不表示后端会自动维护这些条件。

[contract.invariant.boundary]

实现边界

  • 前端 rust-llbc：已支持结构体、枚举和联合体不变式的提取，保留它与类型的关联。同一类型的多个条件目前需用 && 合写，重复属性会产生冲突。
  • 后端 llbc-why3：尚未使用这些条件建立不变式检查；声明不变式还不能保证对象有效。

尚待补齐

从类型条件到检查义务（后端，检查时机待明确）。 下面的类型要求 x <= 100，但创建越界实例目前不会自动产生相应检查：

#[invariant(self.x <= 100)]
pub struct B {
    pub x: u32,
}

pub fn invalid() -> B {
    B { x: 200 }
}

前端会保存 x <= 100；生成的 WhyML 尚未使用它。需要让这条条件参与对象创建、修改及对外使用时的验证。具体在哪些边界检查、是否允许修改过程中暂时不满足条件，以及借用结束时如何恢复，仍待明确。

[contract.grammar]

文法索引

[contract.grammar.intro]

本页集中展示核心文法，便于连续阅读。每条规则的名称都链接到所属主题页，在那里可以查看语义、示例和能力边界。

记号说明见文法记号；运算优先级见条件表达式。本页与各主题页由同一份文法定义生成。

[contract.grammar.syntax]

Syntax
Specification :=
      FunctionContract
    | TypeInvariant
    | ContractStatement

FunctionContract :=
      Precondition
    | Postcondition

Precondition :=
      # [ precondition ( Condition ) ]

Postcondition :=
      # [ postcondition ( ResultPredicate ) ]

ResultPredicate :=
      | IDENTIFIER (: Type)? | Condition

TypeInvariant :=
      # [ invariant ( Condition ) ]

ContractStatement :=
      Assertion
    | Assumption

Assertion :=
      contract_assert ! ( Condition ) ;

Assumption :=
      contract_assume ! ( Condition ) ;

Condition :=
      Expr

Expr :=
      Literal
    | Path
    | self
    | ( Expr )
    | UnaryOp Expr
    | Expr BinaryOp Expr
    | Expr . Field
    | Expr [ Expr ]
    | Expr ( Arguments? )
    | Expr . IDENTIFIER ( Arguments? )
    | Quantifier
    | Implication
    | OldExpression

Arguments :=
      Expr (, Expr)* ,?

Field :=
      IDENTIFIER
    | TUPLE_INDEX

UnaryOp :=
      ! | - | * | & | & mut

BinaryOp :=
      + | - | * | / | % | << | >> | & | ^ | | | == | != | < | <= | > | >= | && | ||

Quantifier :=
      (forall | exists) ! ( QuantifierPredicate )
    | each ! ( IDENTIFIER : Type EachDomain ; Condition )

QuantifierPredicate :=
      | IDENTIFIER : Type | Condition

Implication :=
      Condition ==> Condition
    | implies ( Condition , Condition ,? )

OldExpression :=
      old ( Expr ,? )

[contract.constraints]

实现说明

[contract.constraints.intro]

如何理解实现边界

各构造页分别说明 前端 rust-llbc 和 后端 llbc-why3。这里的前端包括规约宏展开、Rust 类型与借用检查，以及到 LLBC 的提取；后端将 LLBC 中的规约翻译为 WhyML，供验证使用。

前端能够提取，不表示后端已经能够处理；生成 WhyML 文件，也不等于通过 Why3 检查或完成证明。

各页的示例展示已有用法。“尚待补齐”列出具体场景、当前障碍和希望表达的性质；尚未确定的语义标为“待明确”。这些说明不规定开发阶段、优先级或完整支持范围。源码和仓库中的测试见实现依据与测试覆盖。

共同约定

  • Rust 类型与借用规则：条件返回 bool，使用 Rust 的类型系统。除类型不变式方法外，规约闭包受 Fn + Copy 约束；修改捕获变量或移走非 Copy 值可能无法满足这些要求。
  • 普通构建：规约标注会被移除。普通编译通过，不表示规约已经通过验证模式的检查。
  • 正常返回：后置条件描述正常返回时的性质，不同时声明终止或 panic 后的状态。

名称改写

规约宏递归改写 ==> 和 implies，后置条件还改写 old。量词宏自身不做这些改写，需要由外层契约宏处理。

目前替换仅依据名称，同名的普通方法如 value.old() 也会受到影响。前端需要区分规约标记与普通 Rust 名称，具体例子见词法规则。

尚待明确的规则

规约中哪些函数调用可以使用、如何限制副作用，见逻辑表达式。类型不变式在哪些程序边界成立，见类型不变式。这些规则会影响前后端的处理方式，目前保留具体场景，不预先固定完整方案。
