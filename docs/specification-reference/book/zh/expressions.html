[contract.expression]

逻辑表达式

逻辑表达式构成契约、语句标注和类型不变式中的条件。它们使用 Rust 表达式，并扩展了量词、蕴含和旧状态标记。

[contract.expression.syntax]

Syntax
Condition :=
      Expr

Expr :=
      Literal
    | Path
    | self
    | ( Expr )
    | UnaryOp Expr
    | Expr BinaryOp Expr
    | Expr . Field
    | Expr [ Expr ]
    | Expr ( Arguments? )
    | Expr . IDENTIFIER ( Arguments? )
    | Quantifier
    | Implication
    | OldExpression

Arguments :=
      Expr (, Expr)* ,?

Field :=
      IDENTIFIER
    | TUPLE_INDEX

UnaryOp :=
      ! | - | * | & | & mut

BinaryOp :=
      + | - | * | / | % | << | >> | & | ^ | | | == | != | < | <= | > | >= | && | ||

[contract.expression.intro]

类型与值

Condition 必须具有 bool 类型。子表达式可以具有其他 Rust 类型：例如，在 x + 1 <= limit 中，加法产生数值，比较产生布尔值。当前没有独立的谓词类型，也不将整数隐式转换为布尔条件。

名称引用作用域内的绑定。字段访问、解引用、索引、函数调用和方法调用遵循 Rust 的类型与借用规则。圆括号用于分组，不改变表达式的值。

整数表达式使用 Rust 整数类型，遵循其有限取值范围和算术检查。规约接口没有引入数学整数或实数。访问集合元素的表达式同样必须满足索引边界要求；表达式出现在规约中不会免除这一要求。

运算符

下表按优先级从高到低排列。一元运算符右结合，算术和位运算的二元运算符左结合。比较不能直接连写，应写成 a < b && b < c。

分组运算符
访问与调用e.field e[i] f(x) e.method(x)

乘除与取余* / %
加减+ -
移位<< >>

按位异或^
按位或|
比较== != < <= > >=

对布尔操作数，!、&& 和 || 分别表示否定、合取和析取。&& 和 || 短路求值，只有需要时才求值右操作数。单字符的位运算符不提供这种短路行为。

量词绑定某个 Rust 类型的值；蕴含表达条件命题；旧状态表达式说明后置条件中可用的前状态标记。

[contract.expression.example]

示例

use trust2_contract::prelude::*;

#[precondition(i < values.len() && values[i] > 0)]
pub fn positive_at(values: &[u8], i: usize) -> u8 {
    values[i]
}

该条件要求索引有效且对应元素为正。短路求值保证仅在索引合法时才求值第二个操作数。

[contract.expression.boundary]

实现状态

已有前端样例覆盖字段比较、普通调用、切片长度、Vec 索引和 trait 比较，也包括它们与量词的组合。运算符出现在文法中，不代表每种操作数类型或重载都有测试覆盖。

规约体中的调用可以被保留，但外部函数可能是不透明的。当前没有纯逻辑函数、谓词或 ghost 代码的专用声明机制，也没有独立的逻辑序列、集合、映射接口或完整的标准库契约。

这份核心文法未展开块、if、match、类型转换、复杂模式等其他 Rust 形式。这些形式能否接受，取决于具体表达式的解析、Rust 类型检查和提取。
