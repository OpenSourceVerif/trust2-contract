## 如何理解实现边界

各构造页分别说明 **前端 `rust-llbc`** 和 **后端 `llbc-why3`**。这里的前端包括规约宏展开、Rust 类型与借用检查，以及到 LLBC 的提取；后端将 LLBC 中的规约翻译为 WhyML，供验证使用。

前端能够提取，不表示后端已经能够处理；生成 WhyML 文件，也不等于通过 Why3 检查或完成证明。

各页的示例展示已有用法。“尚待补齐”列出具体场景、当前障碍和希望表达的性质；尚未确定的语义标为“待明确”。这些说明不规定开发阶段、优先级或完整支持范围。源码和仓库中的测试见[实现依据与测试覆盖](sources.md)。

## 共同约定

- **Rust 类型与借用规则**：条件返回 `bool`，使用 Rust 的类型系统。除类型不变式方法外，规约闭包受 `Fn + Copy` 约束；修改捕获变量或移走非 `Copy` 值可能无法满足这些要求。
- **普通构建**：规约标注会被移除。普通编译通过，不表示规约已经通过验证模式的检查。
- **正常返回**：后置条件描述正常返回时的性质，不同时声明终止或 panic 后的状态。

## 名称改写 <a id="name-rewriting"></a>

规约宏递归改写 `==>` 和 `implies`，后置条件还改写 `old`。量词宏自身不做这些改写，需要由外层契约宏处理。

目前替换仅依据名称，同名的普通方法如 `value.old()` 也会受到影响。前端需要区分规约标记与普通 Rust 名称，具体例子见[词法规则](notations.md)。

## 尚待明确的规则 <a id="open-areas"></a>

规约中哪些函数调用可以使用、如何限制副作用，见[逻辑表达式](expressions.md#contract.expression.boundary-title)。类型不变式在哪些程序边界成立，见[类型不变式](invariants.md#contract.invariant.boundary-title)。这些规则会影响前后端的处理方式，目前保留具体场景，不预先固定完整方案。
